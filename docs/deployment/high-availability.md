## Overview

Two floating IPs (VIPs) are held by **192.168.68.135** normally and by **192.168.68.136** after a
failover, so that losing .135 doesn't stop payments. Layout and settings:
[Production layout](../overview/production-layout.md).

| VIP | What | Failover |
|---|---|---|
| `192.168.68.150` | HAProxy: `:8545` → rpc1 `:8555` (rpc2 backup), `:9100` → coord1 (coord2 backup) | HAProxy switches backends in about 6 s; keepalived moves the VIP if HAProxy itself fails |
| `192.168.68.151` | the proxy, `:30000` | keepalived moves the VIP, starts proxy2 and stops proxy1 |

| File in `ha/` | Goes to (on .135 and .136) | Generated by Ansible from |
|---|---|---|
| `haproxy.cfg` | `/etc/haproxy/haproxy.cfg` (identical on both) | `ansible/templates/haproxy.cfg.j2` |
| `keepalived-135.conf` / `keepalived-136.conf` | `/etc/keepalived/keepalived.conf` | `keepalived.conf.j2` |
| `check-proxy.sh`, `proxy-start.sh`, `proxy-stop.sh` | `/etc/keepalived/` (chmod 700) | `check-proxy.sh.j2`, `proxy-start.sh.j2`, `proxy-stop.sh.j2` |
| `rpc-health.py` | `/usr/local/bin/besu-rpc-health`, with `/etc/besu-rpc-health.env` | copied as is; settings from `besu-rpc-health.env.j2` |
| `firewall-layout.sh` | run once on **every** host (.135–.139) | run with the plan's addresses |

Why this design:
- **One backend at a time** (rpc2 and coord2 are `backup`): the proxy reads nonces from the same
  RPC node the coordinator sends to, and only one presignature pool is consumed. coord2 runs all
  the time with its pool full, and re-reads the key list from the MPC nodes, so it signs for
  every account the moment it takes over.
- **RPC health from block age and height, not only `eth_syncing`**: a node that stopped importing
  blocks still answers `eth_syncing: false`. See [section 3](#3-rpc-health-besu-rpc-health).
- **Only one proxy at a time**: the proxy counts nonces per sender in memory. keepalived starts
  the proxy on the host that takes `.151` and stops it on the host that gives it up.
  `check-proxy.sh` (every 3 s) also stops a proxy that runs on the host without `.151`, e.g. one
  that Docker restarted after a reboot.
- **RPC nodes on 8555**: HAProxy holds 8545 on the VIP on both hosts, and Besu refuses to start
  when its port is in use on any address of the host, so rpc1/rpc2 can't use 8545 there.
- **`nopreempt`**: after a failover the VIPs stay on .136 when .135 returns (no second
  interruption). Move them back at a quiet time ([section 6](#6-operations)).

## 1. Prepare both hosts (.135 and .136)

```bash
dnf install -y keepalived haproxy python3
```

`python3` runs `besu-rpc-health` (section 3).

```bash
echo 'net.ipv4.ip_nonlocal_bind = 1' > /etc/sysctl.d/90-vip.conf && sysctl --system
```

The sysctl lets HAProxy bind the VIP on the host that doesn't hold it.

With SELinux (check with `getenforce`: `Enforcing` or `Permissive`):

```bash
setsebool -P haproxy_connect_any 1 && setsebool -P keepalived_connect_any 1
```

- `haproxy_connect_any`: HAProxy binds 8404/8545/9100 and connects to rpc1/rpc2 `:8555`, the
  coordinators `:9100` and `besu-rpc-health` on `127.0.0.1:8411`/`8412`.
- `keepalived_connect_any`: keepalived's checks reach HAProxy's health page (`:8404`) and the
  proxy (`:30000`). Without it the HAProxy check fails and `.150` never comes up.

After copying the keepalived scripts (section 5), label them so they may run `docker compose`
(`semanage` is in `policycoreutils-python-utils`):

```bash
semanage fcontext -a -t keepalived_unconfined_script_exec_t '/etc/keepalived/(check-proxy|proxy-start|proxy-stop)\.sh'
```

```bash
restorecon -v /etc/keepalived/*.sh
```

If something is still blocked:

```bash
ausearch -m avc -ts recent
```

Firewall, on **every** host (see `firewall-layout.sh` for what it opens):

```bash
PROXY_CLIENTS="<application IPs>" CHAINLENS_USERS="<explorer users>" GRAFANA_USERS="<dashboard users>" REMIX_USERS="<developers>" ADMIN=<bastion IP> ./firewall-layout.sh 135
```

It writes firewalld rules for the host's own ports, and the same allow list for the ports Docker
publishes (Docker forwards those itself, so firewalld never sees them): nftables table
`inet besu_docker`, rules in `/etc/besu-docker-firewall.rules`, applied at boot by
`besu-docker-firewall.service`. Docker's `DOCKER-USER` chain is not used: Docker re-orders its jumps
on a firewalld reload. Details: [Production layout](../overview/production-layout.md#3-ports-and-firewall).

Network interface name, for the keepalived files (the one with `192.168.68.13x`):

```bash
ip -br addr
```

| proxy `.env` on .135 and .136 | `BESU_IP` and `SIGNER_IP` = `192.168.68.150`, `MPC_ADMIN_URL=http://192.168.68.150:9100` (`proxy/.env.example`) |

## 3. RPC health (besu-rpc-health)

**Why:** an RPC node once stopped importing blocks (after losing its peers) while still answering
`eth_syncing: false`. A check on `eth_syncing` alone kept it on the RPC VIP, serving an old chain.

**What:** `besu-rpc-health` ([`ha/rpc-health.py`](../../ha/rpc-health.py)) is a systemd service on
both HAProxy hosts. It checks every RPC node every 2 s (`eth_getBlockByNumber latest`,
`eth_syncing`, `net_peerCount`) and answers HAProxy on one local port per node:
`127.0.0.1:8410+N` for RPC node N (rpc1 on 8411, rpc2 on 8412). HAProxy uses a node only while its
port answers 200.

A node is **healthy** when all of these hold:

| Check | Setting (`settings.yml`) | Default |
|---|---|---|
| not syncing (`eth_syncing` is `false`) | — | — |
| at most this many blocks behind the best head (of the RPC nodes and the host's own validator) | `rpc_max_blocks_behind` | 10 |
| its newest block is younger than this, unless no node has a newer block (the whole chain is halted) | `rpc_max_block_age` | 30 s |

- **No node healthy:** the most up-to-date reachable node is reported healthy anyway (`degraded`),
  so the VIP keeps answering instead of failing every request.
- **Automatic restart:** an RPC node on the same host that stays stalled or behind for
  `rpc_auto_restart_minutes` (default 5) while the chain moves on is restarted with
  `docker restart` (at most once per period). RPC nodes hold no keys, so this is safe. `0` = never.
  The other host's RPC node is only reported, never restarted.

Settings file: `/etc/besu-rpc-health.env` (`RPC_NODES`, `LOCAL_NODES`, `HEAD_REFERENCE`,
`HOST_HEADER`, `MAX_AGE`, `MAX_BEHIND`, `CHECK_SECONDS`, `RESTART_MINUTES`, `STATUS_PORT`; the
format is in the header of `rpc-health.py`). Ansible writes it from `besu-rpc-health.env.j2`.

Status of every node (height, age, behind, peers, syncing, healthy, reason), as JSON:

```bash
curl -s http://127.0.0.1:8410/
```

Health changes and restarts:

```bash
journalctl -u besu-rpc-health -f
```

The alert `BesuNodeStalled` fires for a node whose newest block is over 60 s old while the chain is
current ([Alerts](../operations/alerts.md)). Symptoms and fixes:
[Troubleshooting](../operations/troubleshooting.md#rpc-and-the-rpc-vip).

**By hand** (Ansible does this in `07-ha.yml`), on .135 and .136:

```bash
install -m 755 ha/rpc-health.py /usr/local/bin/besu-rpc-health
```

`/etc/besu-rpc-health.env` on .135 (on .136: `LOCAL_NODES="rpc2"`; the container names follow the
node directories `/opt/besu-rpc1`, `/opt/besu-rpc2`):

```bash
RPC_NODES="rpc1=http://192.168.68.135:8555=8411=besu-rpc1-besu-1 rpc2=http://192.168.68.136:8555=8412=besu-rpc2-besu-1"
LOCAL_NODES="rpc1"
HEAD_REFERENCE="http://127.0.0.1:8645"
HOST_HEADER="192.168.68.150"
MAX_AGE=30
MAX_BEHIND=10
CHECK_SECONDS=2
RESTART_MINUTES=5
STATUS_PORT=8410
```

`/etc/systemd/system/besu-rpc-health.service`:

```ini
[Unit]
Description=Besu RPC node health for HAProxy (ha/rpc-health.py)
After=network-online.target docker.service
Before=haproxy.service

[Service]
EnvironmentFile=/etc/besu-rpc-health.env
ExecStart=/usr/bin/python3 /usr/local/bin/besu-rpc-health
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
systemctl daemon-reload && systemctl enable --now besu-rpc-health
```

## 4. HAProxy (both hosts)

The `besu_rpc` backend asks `besu-rpc-health` (generated by Ansible from `haproxy.cfg.j2`):

```
backend besu_rpc
    option httpchk GET /
    http-check expect status 200
    server rpc1 192.168.68.135:8555 check addr 127.0.0.1 port 8411 inter 2s fall 2 rise 2
    server rpc2 192.168.68.136:8555 check addr 127.0.0.1 port 8412 inter 2s fall 2 rise 2 backup
```

The hand-written `ha/haproxy.cfg` still checks `eth_syncing` directly against the nodes. For a setup
by hand, replace its `besu_rpc` backend with the one above, then:

```bash
cp haproxy.cfg /etc/haproxy/haproxy.cfg
```

```bash
haproxy -c -f /etc/haproxy/haproxy.cfg && systemctl enable --now haproxy
```

The `mpc_signer` backend checks `GET /health` on each coordinator (`inter 2s fall 3 rise 2`).

## 5. keepalived (both hosts)

On .135 (`keepalived-136.conf` on .136):

```bash
cp keepalived-135.conf /etc/keepalived/keepalived.conf
```

```bash
cp check-proxy.sh proxy-start.sh proxy-stop.sh /etc/keepalived/ && chmod 700 /etc/keepalived/*.sh
```

Edit `/etc/keepalived/keepalived.conf`: `INTERFACE` and both `auth_pass` values (at most 8
characters, the same on both hosts). Edit `PROXY_DIR` in the three scripts if the proxy is not in
`/opt/besu-chain/proxy`. The proxy must already be configured and built on **both** hosts
(`docker compose build`), but **not started**: keepalived starts it on the host that takes `.151`.

| keepalived item | What it does |
|---|---|
| `chk_haproxy` (every 2 s, fall 3) | `curl` to HAProxy's `127.0.0.1:8404/healthz`; on failure `.150` moves |
| `chk_proxy` = `check-proxy.sh` (every 3 s, fall 3) | on the host holding `.151`: the proxy must answer `/status/senders`. On the other host: stops a running proxy and passes |
| `notify_master` = `proxy-start.sh` | `docker compose up -d proxy` when this host takes `.151` |
| `notify_backup` / `notify_fault` = `proxy-stop.sh` | `docker compose stop proxy` when this host gives `.151` up |

The proxy containers have `restart: unless-stopped`, so Docker brings a proxy back at boot on the
standby host too; `check-proxy.sh` stops it within seconds. **On the standby host a stopped proxy
(`docker ps -a` shows `Exited (137)`) is expected.**

Start keepalived on .135 first, then on .136:

```bash
systemctl enable --now keepalived
```

Check who holds the VIPs (both on .135 normally):

```bash
ip -br addr | grep -E '68\.15[01]/'
```

```bash
curl -s http://192.168.68.150:8545 -H 'content-type: application/json' --data '{"jsonrpc":"2.0","id":1,"method":"eth_blockNumber","params":[]}'
```

```bash
curl -s http://192.168.68.151:30000/status/senders
```

| Log | Shows |
|---|---|
| `journalctl -u keepalived` | VIP changes |
| `journalctl -t besu-ha` | proxy started, stopped, or stopped because it ran without the VIP |
| `journalctl -u haproxy` | backend changes |
| `journalctl -u besu-rpc-health` | RPC node health changes and restarts |

## 6. Operations

| Task | How |
|---|---|
| Move the VIPs back to .135 after a failover | at a quiet time, on .136: `systemctl restart keepalived` (it gives up the VIPs; .135 takes them and starts proxy1) |
| Planned maintenance of .135 | `systemctl stop keepalived` on .135 first (clean handover to .136), then the maintenance |
| Change `haproxy.cfg` | the same file on both hosts, `haproxy -c -f …`, `systemctl reload haproxy`. With Ansible: `ansible-playbook 07-ha.yml` (reloads, the VIPs stay where they are) |
| Change the RPC health thresholds | `rpc_max_block_age`, `rpc_max_blocks_behind`, `rpc_auto_restart_minutes` in `settings.yml`, then `ansible-playbook 07-ha.yml` (by hand: edit `/etc/besu-rpc-health.env`, `systemctl restart besu-rpc-health`) |
| Proxy upgrade | build the new image on **both** hosts; on the active host `docker compose up -d proxy` (seconds of downtime). Don't start it on the standby host |
| Coordinator upgrade | coord2 first, then coord1 (HAProxy uses coord2 meanwhile) |

## 7. Failover tests

| Test | Do | Expect |
|---|---|---|
| RPC | on .135: stop rpc1 (`docker compose stop` in its directory) | requests on `.150:8545` keep working via rpc2 within about 6 s; `curl -s http://127.0.0.1:8410/` shows rpc1 unreachable |
| Coordinator | stop coord1 | signing continues via coord2 at once (its pool is full) |
| Proxy | on .135: `docker compose stop proxy` | `.151` moves to .136 within about 10 s, proxy2 starts, `/status/senders` answers on `.151` |
| HAProxy | on .135: `systemctl stop haproxy` | `.150` moves to .136 within about 3–6 s |
| Whole host | power off .135 | both VIPs on .136, proxy2 running; chain continues (3 validators); a few seconds of errors |

Start everything again after each test and check Grafana before the next one. After the proxy,
HAProxy or host test, the VIP stays on .136 (`nopreempt`): don't start proxy1 by hand
(`check-proxy.sh` would stop it); move the VIPs back as in section 6.

## 8. Risks

- **Split brain:** if .135 and .136 can't exchange VRRP messages but both are alive (a firewall
  rule, a broken link), both take the VIPs and both run a proxy. No funds are lost (one
  transaction per nonce), but requests fail. Keep VRRP allowed in both directions, ideally over a
  second link between the two hosts, and check `ip -br addr` on both after network changes.
- **Same subnet only:** the VIPs move within 192.168.68.0/24. Hosts in other sites would need DNS
  or a routed load balancer instead.
- **Keep both hosts identical:** HAProxy file, `besu-rpc-health` settings (except `LOCAL_NODES` and
  `HEAD_REFERENCE`), proxy `.env` and image, coordinator settings.
