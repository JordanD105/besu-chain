## 실행 방법 {#how-to-run}

`mpc-signer/`에서 실행합니다. Docker, bash, curl만 있으면 됩니다.

```bash
bench/run-bench.sh
```

단일 노드 Besu QBFT 체인(`bench/env/`)과 퀵 스타트 클러스터(MPC 노드 3개 + 코디네이터, `quickstart/`)를
시작한 다음 다섯 단계를 실행합니다. 이미 운영 중인 Besu를 대신 사용하려면 `bench/existing.env`(
`existing.env.example`에서 생성)에 `BESU_RPC`를 설정하거나 `BESU_STACK=existing bench/run-bench.sh`를
실행합니다. 실행할 때마다 보고서는 `mpc-signer/bench/results/<time>.md`에, 원시 측정값은
`mpc-signer/bench/results/<time>.jsonl`에 기록됩니다. 옵션(요청 수, 동시성, GMP 백엔드, Docker 대신 호스트
프로세스): [MPC 서명기](../components/mpc-signer.md#benchmark)의 "Benchmark"를 참조하십시오.

| 단계 | 측정 항목 |
|---|---|
| A | 사전 서명 생성 용량: 지속 가능한 서명 상한 |
| B | 서명 처리량(`eth_signTransaction`), 풀을 미리 채우고 보충 일시 중지: 핫 경로 |
| C | 엔드투엔드: 서명 + Besu에 제출 + 채굴될 때까지 대기 |
| D | 콜드 경로: 사전 서명 없이 3+1 라운드의 완전한 대화형 서명 |
| E | 지속 부하: 시작 시 풀이 비어 있고, 부하 중에 보충 실행 |

## 수치 해석 {#reading-the-numbers}

- **모든 것이 VM 1대에서 실행됩니다.** 모든 서명을 검증하는 부하 생성기 자체가 B와 C에서 병목이 됩니다.
  절대 수치는 호스트를 분리한 경우의 하한값입니다.
- **Docker는 측정 가능한 오버헤드를 추가하지 않습니다.** 호스트 프로세스(`MPC_RUNTIME=native`)로 같은
  실행을 하면 초당 3.33개의 사전 서명을 생성했으며, 컨테이너에서는 초당 3.39개였습니다.
- **핫 경로(B): 200–320 TPS.** 사전 서명이 준비되어 있으면 서명 하나에 두 노드로의 병렬 HTTP 라운드 한 번이
  필요하며, 동시성 1에서 약 5 ms입니다.
- **엔드투엔드(C):** 코디네이터는 초당 약 900건의 트랜잭션을 수락합니다. 모두 채굴될 때까지로 계산하면 약
  315 TPS이며, 이는 서명기가 아니라 Besu의 1초 블록 주기로 결정됩니다.
- **지속 처리율은 사전 서명 생성으로 결정됩니다(A, E): 이 VM에서 초당 약 3.4개의 서명.** 풀이 비면 처리량은
  사전 서명 생성 속도(E: 3.1 TPS)나 콜드 경로(D: 서명당 약 0.7초, 동시성 1에서 1.5 TPS, 동시성 4에서
  3.2 TPS)로 떨어집니다.

## MPC 노드 규모 산정 {#sizing-the-mpc-nodes}

사전 서명 하나는 **참여하는 2개 노드 각각에서 약 0.56 CPU 초**가 듭니다(GMP 백엔드, 다중 지수 테이블).
각 노드는 세션의 2/3에 참여하므로 다음과 같습니다.

`cores per node ≈ sustained_TPS × 0.56 × 2/3 ≈ 0.38 × sustained_TPS`

| 지속 TPS | 노드당 코어 수(노드 3개) |
|---:|---:|
| 10 | ~4 |
| 50 | ~19 |
| 100 | ~38 |
| 300 | ~115 |

- 풀은 이 속도를 넘는 버스트를 흡수합니다. 각 코디네이터에서 `big` 키당 `MPC_POOL_TARGET`,
  `small` 키당 `MPC_POOL_TARGET_SMALL`입니다. 풀에 재고가 있는 동안의 최대 처리량은 위의 핫 경로 수치입니다.
- 모든 코디네이터는 자체 풀을 채우므로, 같은 목표값을 가진 코디네이터 두 개는 사전 서명 작업이 두 배가
  됩니다. 대기 코디네이터에 `MPC_POOL_TARGET_SMALL=0`을 설정하면 small 키에 대해서는 이를 피할 수 있습니다
  ([운영 환경의 MPC 서명기](../deployment/mpc-signer-production.md#presignature-pools-big-small-and-none)).
- 순수 Rust 백엔드(`bigint-num`)는 GMP보다 사전 서명이 몇 배 느립니다. `BIGINT=bigint-rug` 없이 빌드하는
  경우 이를 고려하여 규모를 산정하십시오.
- 처리율을 높이려면 노드에 코어를 더 할당하고 `MPC_COMPUTE_THREADS`(노드)와
  `MPC_REFILL_CONCURRENCY`(코디네이터)를 높이십시오.
